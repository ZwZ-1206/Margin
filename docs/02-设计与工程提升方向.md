## 第一部分 · 视觉设计规范（Design Lead 产出）

### 0. 定位与品牌记忆点

「留白」——屏幕使用时间管理 + 专注番茄钟 App。品牌记忆点：**「留白之环」**：一个不闭合的圆环（缺口 60°，朝 2 点钟方向），缺口处一粒光点。寓意"给屏幕时间留白"，贯穿 Logo、进度环、启动页、通知图标。

### 1. 设计原则（相对原版的差异）

| # | 原则 | 相对原版的提升 |
|---|---|---|
| P1 | 界面即产品理念 | 原版深色+高密度信息堆叠，气质偏"监控工具"；新版大留白、低密度、克制动效，打开 3 秒内感到"慢下来" |
| P2 | 数据叙事而非罗列 | 每个数字带上下文：同比 delta、目标完成度、自动洞察文案；原版只有原始数值 |
| P3 | 浅色主题独立设计 | 浅色为"暖纸"体系、深色为"墨青"体系，两套对等设计；原版深色优先、浅色附属 |
| P4 | 专注页是产品高潮 | 进入专注自动降噪：压暗背景、隐藏底部导航、收起次要信息；原版专注页与普通功能页同级 |
| P5 | 克制的品牌符号系统 | 全部自绘控件统一收敛到"圆环+光点"语言；原版 navy 蓝为纯功能色，无符号资产 |
| P6 | 无障碍原生 | 对比度/动态字体/折叠屏在 token 阶段内置；原版几乎未涉及 |

### 3. 核心页面设计要点

**首页**：问候顶栏（56dp）→ Hero 总览卡（双环同心：外环 232/14dp 屏幕目标完成度 + 内环 184/8dp 专注占比；中心 Display-L 等宽数字 + delta 徽标；环下三等分 StatPill：解锁次数/专注时长/限额余量）→ 限额卡（8dp 进度条 + **预测超时时间**）→ 最常用 App 横滑卡（144dp）→ 今日专注摘要。改进：单环→双环、数字滚动动画+同比、限额预测、信息三级分化。

**专注页**：模式分段控件（番茄钟/倒计时/正计时）→ 280/16dp 渐变计时大环 + Display-XL 中心数字 + 番茄进度点 → 控制区（64dp 主按钮 pill、**长按 800ms 结束**环形填充确认、48dp 副按钮）→ 白噪音 chip 组 → **专注 mini 悬浮条**（48dp 常驻）。改进：开始后背景压暗一档+隐藏次要信息的沉浸模式、分钟/秒十位个位 120ms 垂直微翻页、克制庆祝（24 粒子迸发+一次触觉，不用整屏彩带）、横屏/平板控制 dock 改左右并排。

**统计页**：周期分段（日/周/月）→ 核心指标卡 → 主图表卡（柱状/**饼图/时段块图**三 tab；柱宽 12dp 间距 8dp；**本周 vs 上周并列柱**（上周 30% 透明度）；3 条虚线网格；十字准线+tooltip）→ App 排行（Top10，64dp 行，携带时长进度+较上周变化双信息）→ **自动洞察卡**（"本周三 21:00 使用最长，试试安排一场专注"+换一批）。改进：静态图表→可交互、纵向参照、数据翻译成行动建议、骨架屏 shimmer。

**设置页**：分组列表卡。主题选择改**可视化预览卡**（96×64dp 三张横排，原版是文字列表）；限额滑块+快捷 chip；StepperRow（−/+ 40dp 触控）；每行右侧常驻当前值摘要；危险操作统一 Bottom Sheet 二次确认。

### 4. 动效规范

时长 token：micro 120 / small 200 / medium 320 / large 480 / xlarge 720ms。
曲线：standard `cubic-bezier(0.2,0,0,1)` / decelerate `(0,0,0,1)` / accelerate `(0.3,0,1,1)` / overshoot `(0.34,1.56,0.64,1)` / spring(damping 0.75, stiffness 380)。

- 底部 Tab：fade-through（旧页 90ms 淡出+scale 0.97，新页 210ms 淡入）
- 专注页进入：shared-axis Z scale 0.92→1，480ms
- 专注开始：按钮弹回 120ms spring → 环描边 480ms decelerate → 阶段标签延迟 120ms 淡入 → 呼吸光晕 2400ms 循环
- 完成庆祝总 480ms：环闪白 120ms → 24 粒子迸发（overshoot）→ 数字卡 spring 回弹 → 确认触觉 → 文案延迟 400ms 淡入
- 图表：柱状逐根生长 stagger 24ms；环形扫开 480ms
- 大数字变化 720ms decelerate 插值；系统"移除动画"开启时全部降为 0，仅留 120ms 淡入

### 5. 图标与插画

线性为主：24dp 网格、stroke 1.8dp、round cap/join；仅选中态/已完成/警告用面性变体。尺寸阶梯 20/24/28/32/40dp。插画为几何拼贴（只用圆环、圆角矩形、直线、圆点四元素，双色，无人物无 3D，留白≥40%）。空状态三场景：无数据/无权限（盾+环，引导开启"使用情况访问"）/无专注记录。

### 6. 无障碍与适配

- 对比度：正文 ≥4.5:1、大文本与图形 ≥3:1（全部 token 组合已验算）；承载交互语义的边框必须 ≥3:1
- 动态字体：全部 sp，支持 200% 缩放；容器用 minHeight；100%/150%/200% 三档全页面回归
- 折叠屏/平板：Compact 单栏+底部导航；Medium 内容 640dp 居中+首页双列；Expanded Navigation Rail 80dp；铰链 16dp 缓冲带内不放关键交互
- 专注模式：时间数字 `#F2F4F7` on `#07080B`（>16:1），控制按钮触控 ≥64dp

|---|---|---|---|

**Room vs Realm 判定依据**：realm-jni 占原版包体 20% 且 Kotlin SDK 停止活跃特性开发；Room 用框架内置 SQLite，dex 增量约 1MB，聚合统计在 DB 侧完成，DAO 返回 Flow 与 Compose 零胶水，迁移有自动化测试体系。统计数据不敏感，不引入 SQLCipher。

### 2. 模块划分与依赖规则

```
:app / :benchmark / :baselineprofile / :build-logic
:core:common  :core:domain  :core:model  :core:database  :core:datastore
:core:network :core:designsystem :core:ui :core:testing
:domain:usage :domain:focus :domain:membership      ← 纯 Kotlin/JVM，零 Android import
:data:usage   :data:focus   :data:membership
:feature:home :feature:focus :feature:stats :feature:profile :feature:onboarding :feature:membership
:sync（UsageReconcileWorker / CloudSyncWorker / FocusFinalizeWorker）
```

CI 强制规则：① `:domain:*`/`:core:*` 不得 import `android.*`（用 `java-library` 插件物理隔离）；② Feature 不得直接依赖 `:data:*` 或其他 Feature；③ Room/Ktor 只有 `:core:database`/`:core:network` 能引入；④ 任何模块不得依赖 `:app`。由 `:build-logic` convention 插件构建时扫描，违规即 fail。

### 3. 分层架构

UDF 数据流：用户操作 → Composable 回调 → ViewModel.onEvent → UseCase（Flow/suspend）→ Repository（单一数据源仲裁）→ Room DAO(Flow)/UsageStats 采集器/Ktor/DataStore → Result/Flow 上行 → ViewModel reduce 为不可变 UiState → `collectAsStateWithLifecycle` 渲染。一次性副作用走 `Channel<UiEffect>`。

错误处理：`AppError` 密封类（Network/Permission/NoUsageData/SessionCorrupted/MembershipExpired/Unknown），Data 层统一归一，ViewModel 映射为用户可读文案+重试动作；**采集数据缺口不作为异常**，是 `dataQuality` 标记，UI 降级提示"部分数据为估算值"。

### 4. 后台监控引擎（替代原版轮询）

采集策略：`queryEvents(since, now)` **事件驱动 + 增量聚合**——
- 以 `ACTIVITY_RESUMED/PAUSED` 配对成区间；同 package 重叠区间取并集（覆盖分屏）；跨午夜按本地时区切分；锁屏未闭合区间截断到 `SCREEN_NON_INTERACTIVE`
- 持久化 `last_event_ts` 游标，查询带 2–5 分钟重叠窗口，按 `(package, start_ts)` 幂等去重，容忍上报延迟
- 单事务 upsert 原始区间 + 重算当日聚合

三级触发：**L1 实时**（前台服务内屏幕广播 + 自适应 tick，无事件降频至 5min）→ **L2 周期**（WorkManager 30min 对账补偿+缺口修复）→ **L3 精确**（AlarmManager 心跳保活 + 番茄闹钟 + Doze 兜底）。

前台服务规范：类型 `dataSync`（Android 14+ 强制）；低重要性常驻通知显示今日已用时长；`START_STICKY` + onDestroy 经 AlarmManager 1 分钟后重启；**不持 WakeLock、不固定轮询**（原版耗电根因）。

厂商保活兜底：诚实的数据缺口模型——统计屏幕点亮总时长与已覆盖区间之差，缺口>5min 置标记并修复：① 重放 queryEvents → ② 日桶差额补偿并标 `estimated` → ③ UI 显示估算徽标；引导用户加电池白名单。

### 5. 专注计时引擎

状态机（`:domain:focus` 纯 Kotlin 零 Android 依赖）：
```
Idle ─start▶ FocusRunning ─pause▶ FocusPaused ─resume▶ FocusRunning
                │ complete                │ complete
                ▼                         ▼
           ShortBreak ──▶ FocusRunning（下一轮）   LongBreak（每 4 个专注后）
任意运行态 ─stop/interrupt▶ Interrupted（归档，不计完成数但计入总投入）
任意态 ─进程死亡▶ Restore（Checkpoint 重建）
```

- **唯一时间源**：注入的 `ElapsedTimeProvider`（`SystemClock.elapsedRealtime`），绝不用 `currentTimeMillis`（改表/时区/NTP 不影响计时），单测用 Fake 虚拟时间
- **Checkpoint**：每 5 秒 + 每次状态跃迁 + onDestroy 原子写入；恢复时若 `elapsed ≥ remaining` 判定"期间已完成"直接结算
- **双保险**：结束前注册 `setExactAndAllowWhileIdle` 闹钟，进程被杀也由 `FinalizeReceiver` 按 Checkpoint 结算
- 服务与 UI 订阅**同一个 StateFlow**，通知与界面永不漂移

### 7. 性能预算

冷启动 P95 <1.5s（Baseline Profile + Application 零初始化）；掉帧 <1%（稳定性推断+Lazy key）；**包体下载体积 ≤15MB**（dex ≤4.5MB / 资源 ≤1.5MB / 原生 ≤1MB / 音频 ≤1.5MB Opus 按需 / 字体 ≤0.5MB，不自带 emoji 字体）；后台耗电 ≤2%/天（采集 ≤12 批/小时，无 WakeLock）。

## 第三部分 · 两份文档的协同关系

- 登录与会员体系（文档 01）落在 `:feature:membership` + `:domain:membership` + `:data:membership`，其权益缓存（DataStore）与票据校验（Play Billing）已在架构文档第 1/5 节预留位置；
- 设计规范（第一部分）的全部 token 落地为 `:core:designsystem` 的 Color/Type/Shape/Dimension 常量，自绘控件（环/翻页时钟/图表）按 Compose Canvas 重写于各 feature；
- 两套文档的共同出口：**M1 里程碑——无后端可跑、包体 ≤15MB、核心功能全本地可用**。
