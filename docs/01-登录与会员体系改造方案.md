# OffScreen 复刻版 · 登录与会员体系改造方案

> 版本：v1.0 ｜ 日期：2026-10-19 ｜ 状态：设计稿，待评审
> 输入依据：原版 OffScreen v1.2.4 APK 逆向分析（包名 `tech.miidii.offscreen_android.domestic`）
> 目标：不做 1:1 复刻，在身份、会员、安全、合规四个维度做代际提升

---

## 0. 原版诊断与改造原则

### 0.1 原版实际形态（逆向实证）

| 环节 | 原版实现 | 问题 |
|---|---|---|
| 注册登录 | 手机号 + 短信验证码（`LoginActivity`，6 位码） | 强制登录才能用高级功能；后端 `api.members.miidii.tech` 已停运，链路整体断裂 |
| 会话管理 | 包内未见 token 刷新/设备管理痕迹 | 无会话概念，疑似长 Hash 单令牌，无法远程注销 |
| 会员 | 「终身会员」布尔买断（微信/支付宝直付） | ① 布尔位无法表达试用/退款/过期；② 微信/支付宝直付虚拟商品违反 Google Play 政策；③ 客户端本地标志位可被篡改 |
| 账号注销 | 有注销流程与风险告知文案 | 合规意识好，但级联删除范围依赖服务端实现（不可考） |
| 数据 | 全部本地 Realm，无云同步 | 换机即丢数据，只能本地备份文件迁移 |

### 0.2 改造原则（六条）

1. **本地优先 + 渐进式认同**：下载即可用，匿名身份承载全部本地功能；仅在「云同步/买会员/换机」时引导绑定正式账号。原版"强制登录"是最大体验缺陷。
2. **一个 User，多个 Identity**：手机/微信/Google/Apple/匿名都是 Identity，可随时增绑解绑，不重复建号。
3. **权益（Entitlement）模型取代布尔会员位**：服务端签发、本地缓存、离线宽限、可撤销可退款。
4. **支付合规化**：Android 侧虚拟商品一律走 Google Play Billing；微信/支付宝仅用于合规允许的场景或 Web 侧。
5. **安全默认**：Token 进 Keystore、短寿命 Access + 轮换 Refresh、生物识别二次验证、Play Integrity 防篡改。
6. **合规内建**：个保法同意流、注销级联删除、数据导出、审计日志。

## 1. 用户注册与登录流程

### 1.1 身份状态机

```
[匿名态 Anonymous]  ←—— 首次启动静默创建（device-bound）
      │
      │ 触发绑定：开启云同步 / 购买会员 / 换机迁移
      ▼
[待验证 Unverified] —— OTP 验证 / OAuth 回调 ——▶ [已绑定 Bound]
      │                                              │
      └—— 放弃绑定，回退匿名态（本地功能不受影响）     │ 可增绑更多 Identity
                                                     ▼
                                              [正常态 Active]
                                                     │ 用户注销 → [注销中 30 天缓冲] → [已删除]
```

要点：
- **匿名身份**：本地生成 UUID + Keystore 内设备密钥，服务端为其签发 scope=anonymous 的短期令牌，保证后续所有请求可审计、可平滑升级为正式账号。
- **绑定时机**：只在不打断核心任务流的自然节点提示（如购买前、设置页入口），绝不弹窗拦截。
- **登录方式优先级**：手机号 OTP（主）＞ 微信 OAuth（国内转化率最高）＞ Google（Play 渠道必备）＞ Apple（iOS 端）。
- **账号合并**：匿名数据 merge 到正式账号，按记录级 last-write-wins + 冲突列表让用户确认；专注记录、统计数据这类不可再生的高价值数据，冲突时保留双方副本并标注来源。

### 1.2 OTP 规则（服务端强制）

| 规则 | 值 |
|---|---|
| 码长/有效期 | 6 位 / 5 分钟 |
| 发送间隔 | 同一号码 60 秒；同一设备 24 小时 10 条 |
| 验证失败 | 连续 5 次失败锁该号码 1 小时 |
| 防枚举 | 请求接口对"已注册/未注册"返回完全一致的响应体与耗时 |
| 人机校验 | 异常设备/IP 先过验证码或 Play Integrity 再发码 |

### 1.3 微信 / Google / Apple 登录

- 微信：官方 SDK，`UnionID` 作为 Identity 唯一标识（注意 openid 按 App 维度不唯一，必须用 UnionID）。
- Google：用 **Credential Manager API**（已替代旧 GoogleSignIn），支持"使用 Google 账号登录"一键流。
- Apple：iOS 端 Sign in with Apple；Android 端通过 Web 流程。
- OAuth 统一抽象为 `OAuthProvider` 接口，新增渠道只加实现，不动上层。

## 2. 身份认证与会话管理

### 2.1 令牌体系

| 令牌 | 寿命 | 载体 | 说明 |
|---|---|---|---|
| Access Token（JWT，RS256） | 15 分钟 | 仅内存 | claims：`sub`(user_id)、`scope`、`ent_epoch`(权益版本号)、`dev_id`、`jti` |
| Refresh Token | 30 天 | EncryptedSharedPreferences（MasterKey 在 Keystore） | 一次性使用，轮换下发；**重放检测**：旧 token 再次使用 → 判定泄露，立即吊销该会话全家桶并告警 |

- Access Token 过期由 OkHttp `Authenticator` 无感刷新，UI 层零感知。
- 匿名态同样持令牌（scope=anonymous），服务端统一审计。
- 禁止在任何日志/SD卡/备份文件中出现完整 token；备份导出内容不含令牌。

### 2.2 会话与设备管理

- 每个登录设备一条 Session 记录（设备型号、系统、登录时间、最近活跃、IP 归属地粗粒度）。
- 「设置 → 账号与安全 → 登录设备管理」：列表展示 + 单个/全部远程注销。
- **敏感操作二次验证**：购买、注销、导出数据、解绑全部 Identity 前，必须生物识别（BiometricPrompt）或重新 OTP。
- 新设备首次登录：发送登录提醒通知（含"不是本人操作"一键踢下线+改密链接）。

### 2.3 认证服务选型

| 方案 | 适用 | 结论 |
|---|---|---|
| 自建最小认证服务 | 要完全掌控数据、后端成本可控 | **本期采用**（接口按标准抽象，可整体替换） |
| Firebase Auth / Supabase Auth | 快速起步、无运维 | 二期备选；原版 Firebase 已停运，不复用其工程 |
| Keycloak 等 IAM | 未来 B 端/家庭版 | 预留迁移路径 |

> 无论自建还是托管，客户端只依赖本文第 6 节的接口契约，实现可替换。

## 3. 会员等级与权限控制

### 3.1 商品与权益模型

```
Plan（商品定义，服务端配置）
  ├─ free           免费版
  ├─ pro_lifetime   买断制（保留原版心智，主推）
  └─ pro_yearly     订阅制（新增，可选）

Entitlement（权益实例，服务端签发）
  user_id + plan_id + source + status + valid_from/to/grace_until
  source: play_billing | wechat | alipay | grant(赠送/迁移兑换)
  status: active | expired | revoked | refunded | pending

Capability（能力开关，客户端查询单元）
  例：history_data / yearly_stats / unlimited_tags / advanced_challenges
```

原版 Pro 门槛点（从资源字符串提取，复刻时逐条映射为 Capability）：
- 「升级至 Pro 用户后可查看历史数据」「The history data is only available to Pro members.」→ `history_data`
- 「解锁所有的时间测量」→ `advanced_stats`
- 「创建无限个专注标签」→ `unlimited_tags`
- 时间线历史、月度/年度分析 → `timeline_history` / `periodic_reports`

### 3.2 校验链路（三层）

1. **服务端为唯一真相源**：所有购买凭据（purchase token）必须经服务端调用 Google Play Developer API 验证 + RTDN 实时到账通知，客户端绝不采信本地"已购买"标志（原版最大安全隐患）。
2. **本地缓存**：`EntitlementCache`（DataStore）存权益快照，含 `grace_until`，日常查询走本地，零延迟。
3. **离线宽限**：缓存权益过期后给 7 天宽限期（`grace_until`），期间功能可用但顶部提示"联网刷新权益"；超宽限才降级。避免"坐飞机/断网就用不了"的荒谬体验。

### 3.3 支付合规

- Android：Google Play Billing Library，商品分 `inapp`（买断）与 `subs`（订阅）；服务端校验 + RTDN 对账；支持 `acknowledge` 与 `consume` 语义。
- 微信/支付宝：**仅用于** Play 渠道之外分发（官网 APK、Web）或实体商品场景；若只在 Play 上架，则完全移除，避免政策下架风险。
- 老用户迁移：原版终身会员凭本地备份文件或订单号，走一次性兑换码（`grant` source）通道，服务端人工/半自动审核发放。

## 4. 用户数据模型

### 4.1 服务端 ER（核心 8 表）

| 表 | 关键字段 | 职责 |
|---|---|---|
| `user` | id, status(active/deleting/deleted), created_at, deleted_at | 账号主记录 |
| `identity` | id, user_id, type(phone/wechat/google/apple/anonymous), identifier, verified_at | 多身份，`(type, identifier)` 唯一 |
| `device` | id, user_id, platform, model, os_version, push_token, trusted, last_seen_at | 设备与会话管理 |
| `session` | id, user_id, device_id, refresh_token_hash, expires_at, revoked_at, last_ip | 会话，只存 Hash |
| `membership` | id, user_id, plan_id, source, purchase_token, status, valid_from, valid_until, grace_until | 权益实例 |
| `capability_grant` | user_id, capability, granted_until, reason | 能力级授权（运营发放/灰度） |
| `consent` | user_id, type(privacy/agreement/marketing), version, granted_at, ip | 个保法同意记录 |
| `audit_log` | id, user_id, action, target, ip, ua, created_at | 敏感操作审计（登录/购买/注销/导出） |

### 4.2 客户端本地模型

- Room：`user_local`、`entitlement_cache`、`sync_outbox`（离线操作队列，重放幂等）、既有业务表不变。
- DataStore(Proto)：会话 token 块、专注 Checkpoint、引导状态。
- **原则**：本地永远先可写，云端是增强而非依赖——复刻版即使后端全挂，监控/专注/统计/限额全部可用。

## 5. 安全策略

| 面 | 措施 |
|---|---|
| 传输 | TLS 1.2+（推荐 1.3），证书固定（`network_security_config`，内置 pin + 备用 pin 防自锁） |
| 存储 | Token 在 EncryptedSharedPreferences（Keystore MasterKey）；Room 不加密（统计数据非敏感）；票据/收据入 DataStore Proto |
| 令牌 | 15 分钟 Access + 30 天轮换 Refresh + 重放检测 + 设备绑定（`dev_id` claim） |
| 防刷 | OTP 频率限制、Play Integrity API 设备鉴真（原版已含 Play Core，复用）、异常行为风控打分 |
| 支付 | 服务端验单 + RTDN；客户端只上传 purchase token；退款/拒付走 `revoked/refunded` 状态机 |
| 隐私 | PII 最小化收集；日志脱敏（手机号打码）；导出数据为纯 JSON 不含令牌；注销 30 天缓冲期后级联物理删除（含审计日志匿名化） |
| 密钥 | JWT 签名密钥托管 KMS/HSM，支持轮换（kid 头多密钥并存） |

## 6. 接口设计（REST，版本化 `/v1`）

统一约定：JSON；错误信封 `{code, message, trace_id}`；写接口支持 `Idempotency-Key` 头；限流信息走响应头。

**认证**
```
POST /v1/auth/otp/request          {phone}                 → 204（恒成功，防枚举）
POST /v1/auth/otp/verify           {phone, code}           → {access_token, refresh_token, is_new_user}
POST /v1/auth/oauth/{provider}     {code | id_token}       → {access_token, refresh_token, is_new_user}
POST /v1/auth/token/refresh        {refresh_token}         → {access_token, refresh_token}（轮换）
POST /v1/auth/logout               -                        → 204
POST /v1/auth/logout/all           -                        → 204
```

**账号**
```
GET    /v1/me                       → profile + devices + membership 摘要
POST   /v1/me/identities            {type, credential}    → 绑定新身份
DELETE /v1/me/identities/{id}       -                      → 解绑（敏感操作，需二次验证头）
POST   /v1/me/devices/{id}/revoke   -                      → 踢设备下线
DELETE /v1/me                       -                      → 注销（30 天缓冲）
GET    /v1/me/export                -                      → 全量数据 JSON（异步任务+下载链接）
GET/PUT /v1/me/consents             -                      → 同意记录读写
```

**会员**
```
GET  /v1/memberships/me             → 当前权益 + capability 列表 + grace_until
POST /v1/memberships/verify         {product_id, purchase_token} → entitlement（Play 验单）
POST /v1/memberships/redeem         {code}                → 兑换码发放权益（grant）
```

**同步（可选云备份，M3 里程碑）**
```
POST /v1/sync/push                  {ops[]}                → {accepted, conflicts[]}
GET  /v1/sync/pull?since={cursor}   -                       → {changes[], next_cursor}
```

错误码规范：`4001 参数错误 / 4010 令牌过期 / 4011 令牌重放 / 4030 权限不足 / 4090 冲突 / 4290 限流 / 5000 内部错误`。

## 7. 客户端核心模块职责

| 模块 | 职责 | 关键实现要点 |
|---|---|---|
| `AuthModule` | OTP/OAuth 流程编排、匿名身份创建与升级 | 流程用状态机表达；Credential Manager 封装 Google；微信 SDK 隔离在独立实现类 |
| `SessionModule` | Token 生命周期、自动刷新、设备管理 | OkHttp Authenticator + 互斥刷新（防并发 401 雪崩）；token 仅经 encrypt 存储 |
| `MembershipModule` | 权益缓存、Capability 查询、购买流程 | `isGranted(cap)` 同步 API 供全 App 调用；Play Billing 连接/商品/购买/ acknowledge 全流程；离线宽限 |
| `AccountModule` | 资料、身份管理、注销、导出 | 敏感操作统一走二次验证拦截器 |
| `NetworkModule` | OkHttp/Ktor 拦截器链 | 顺序：trace → auth → retry → 签名；401 只由 Authenticator 处理，拦截器不擅自重试 |
| 各 Feature | 只依赖 `MembershipModule.isGranted()` 与 `SessionModule` 状态 | 依赖倒置：Feature 不认识 token/JWT 的存在 |

## 8. 可扩展方向

1. **认证服务整体替换**：接口按 §6 抽象，自建 → Firebase Auth/Supabase/Keycloak 可平移，客户端零改。
2. **家庭/青少年模式**：`user` 上加 family 关系表，Capability 增加 parental 域，服务端加家庭组 API。
3. **B 端/团队版**：复用 identity/session/entitlement，增加组织维度与 SSO。
4. **订阅制转型**：Entitlement 已支持 `valid_until`，加 `subs` 商品即可，无需改客户端模型。
5. **跨端**：iOS 复用时同一 API 契约；离线冲突策略可从 LWW 升级为 CRDT（专注记录场景收益大）。
6. **风控演进**：audit_log + Integrity 信号积累后上设备信任分，异常登录自动升级验证强度。

## 9. 落地路线（四个里程碑）

| 里程碑 | 范围 | 出口标准 |
|---|---|---|
| **M1 无后端可跑** | 匿名身份 + 本地权益缓存 + Play Billing 本地购买 + 全功能本地可用 | 全新安装不登录可用全部核心功能；买断在沙箱环境端到端通过 |
| **M2 最小后端** | auth（OTP/OAuth/refresh）+ membership verify + RTDN 对账 | 登录-购买-验单-权益下发全链路；重放/限流单测覆盖 |
| **M3 云同步** | sync push/pull + 换机迁移 + 账号合并 | 双设备数据一致；冲突用例有明确 UX |
| **M4 安全合规完备** | Play Integrity、审计日志、导出、注销级联删除、同意流 | 过一遍个保法 checklist；安全评审通过 |

> 建议：M1 与 App 主体复刻并行推进——登录体系不阻塞本地功能开发，这是相对原版"登录绑死一切"最实质的架构改进。
